# reservix-crypto

Электронная подпись документов и защищённый журнал аудита для системы
кадрового резерва [Reservix](https://github.com/ht2473/Reservix) на
отечественных алгоритмах: ГОСТ Р 34.10-2012, ГОСТ Р 34.11-2012 (Стрибог),
ГОСТ Р 34.12-2015 (Кузнечик), Р 50.1.111-2016, Р 50.1.113-2016.

## Зачем

В Reservix целостность документа проверяется по SHA-256, который лежит в той
же таблице, что и документ. Если есть доступ к базе и файлам, можно поправить
файл, пересчитать сумму, и `verify_documents` ничего не заметит. Журнал аудита
защищён только запретом `save()`/`delete()` в модели, а обычный `UPDATE`
или `DELETE` в базе его обходит.

Здесь это закрыто так:

- документ подписывают сотрудник и кадровая служба (ГОСТ Р 34.10-2012);
  ключи выдаёт свой УЦ, корневой сертификат хранится вне базы;
- закрытые ключи лежат в файлах, зашифрованных паролем
  (PBKDF2 → Кузнечик-CTR + HMAC);
- записи журнала связаны цепочкой HMAC-Стрибог-256, ключ хранится вне базы;
  удаление последних записей ловят контрольные точки, подписанные службой аудита.

## Запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/). PostgreSQL и Docker не нужны,
демо работает на SQLite.

```
uv sync
uv run python demo/run_all.py --pause
```

Или по шагам:

```
uv run python demo/01_keys.py             # УЦ, сертификаты, ключи
uv run python demo/02_sign_document.py    # загрузка акта и подписание
uv run python demo/03_attack_document.py  # атаки на документ
uv run python demo/04_audit_chain.py      # журнал аудита и атаки на него
```

`01_keys.py` каждый раз создаёт каталог `workspace/` заново. Атаки в шагах 3 и 4
идут на копии, после каждой всё откатывается.

Тесты:

```
uv run pytest
```

## Что показывает демо

| Атака | SHA-256 (как в Reservix) | Здесь |
|---|---|---|
| Поправить файл акта и пересчитать SHA-256 | не видно | подпись недействительна |
| Переподписать своим ключом от имени сотрудника | не видно | сертификат не от УЦ |
| Скопировать подписи на другой документ | не видно | атрибуты не совпадают |
| Кадровик подписывает вместо сотрудника | не видно | нарушена политика подписей |
| `UPDATE` записи журнала | не видно | звено не сходится |
| `DELETE` записи журнала | не видно | разрыв цепочки |
| Удалить запись и пересчитать цепочку | не видно | без ключа HMAC не пересчитать |
| Удалить последние записи | не видно | не сходится с контрольной точкой |

## Структура

```
reservix_crypto/
  gost.py          Стрибог, HMAC, PBKDF2, Кузнечик, подпись ГОСТ Р 34.10-2012
  keystore.py      файлы закрытых ключей
  pki.py           УЦ и сертификаты
  reservix.py      хранилище документов из Reservix (SHA-256), без Django
  signing.py       подпись и проверка документов
  audit_chain.py   цепочка журнала и контрольные точки
  workspace.py     схема SQLite и каталоги
demo/              шаги 01-04, run_all.py, data/ с исходным актом
tests/             тесты, в том числе контрольные примеры из стандартов
```

## Про реализацию подписи

Стрибог, HMAC, PBKDF2 и Кузнечик взяты из
[gostcrypto](https://pypi.org/project/gostcrypto/). Подпись в gostcrypto
работает минутами на одну операцию, поэтому ГОСТ Р 34.10-2012 написан заново
(`gost.py`, около 100 строк). Подпись занимает ~9 мс, проверка ~13 мс.
Правильность проверяется контрольным примером из приложения А стандарта
(`tests/test_gost_vectors.py`): ключ Q и подпись (r, s) совпадают полностью.

Порядок байтов: Стрибог в gostcrypto возвращает хеш в обратном порядке
относительно записи в стандарте, поэтому хеш читается как little-endian
(`digest_to_int`).

## Ограничения

Это учебный код, а не сертифицированное СКЗИ. Скалярное умножение не
константное по времени, нет отзыва сертификатов и меток времени. Для
реального применения нужен КриптоПро CSP или аналог и ключи на токенах.
